# সিস্টেম মনিটরিং ও ত্রুটি পর্যবেক্ষণ নির্দেশিকা (Monitoring & Troubleshooting Guide)

এই নির্দেশিকাটি দোকানের মালিক এবং সিস্টেম অ্যাডমিনিস্ট্রেটরের জন্য তৈরি করা হয়েছে, যাতে সার্ভারে কোনো সমস্যা হলে তাৎক্ষণিকভাবে তা চিহ্নিত এবং সমাধান করা যায়।

## ১. সার্ভার লগ পর্যবেক্ষণ (Reading Server Logs)

সার্ভারের ব্যাকএন্ড এপিআই প্রতিটি রিকোয়েস্ট একক লাইনের স্ট্রাকচার্ড JSON ফরম্যাটে লগ করে। লগগুলোতে পাসওয়ার্ড, অথেন্টিকেশন টোকেন, পিন কোড এবং গ্রাহকদের মোবাইল নম্বর স্বয়ংক্রিয়ভাবে মাস্ক (mask) করা থাকে (যেমন: `+88017*****344`)।

### সাধারণ লগ কমান্ডসমূহ:

1. **রিয়েল-টাইম লাইভ লগ দেখা (সব সার্ভিস):**
   ```bash
   docker compose -f deploy/docker-compose.prod.yml logs -f
   ```

2. **শুধু এপিআই (API) সার্ভারের লাইভ লগ দেখা:**
   ```bash
   docker compose -f deploy/docker-compose.prod.yml logs -f api
   ```

3. **সর্বশেষ ১০০ লাইন লগ দেখা:**
   ```bash
   docker compose -f deploy/docker-compose.prod.yml logs --tail=100 api
   ```

4. **শুধুমাত্র এরর (Error) লগ ফিল্টার করা:**
   ```bash
   docker compose -f deploy/docker-compose.prod.yml logs api | grep '"level":"error"'
   ```

5. **ডাটাবেস মাইগ্রেশন লগের অবস্থা দেখা:**
   ```bash
   docker compose -f deploy/docker-compose.prod.yml logs migrate
   ```

## ২. হেলথ চেক এন্ডপয়েন্ট (Health Check Endpoints)

সিস্টেমের সার্বিক সুস্থতা যাচাই করার জন্য দুটি প্রধান এন্ডপয়েন্ট রয়েছে:

1. **`/api/v1/health/live` (Liveness Probe):**
   - **উদ্দেশ্য:** এপিআই প্রসেস চালু আছে কি না যাচাই করে।
   - **রেসপন্স:**
     ```json
     {
       "status": "ok",
       "uptime": 12450.8,
       "timestamp": "2026-11-22T16:30:00.000Z"
     }
     ```

2. **`/api/v1/health/ready` (Readiness Probe):**
   - **উদ্দেশ্য:** Caddy এবং Docker রিভার্স প্রক্সি এই এন্ডপয়েন্ট ব্যবহার করে ট্রাফিক পাঠানোর আগে ডাটাবেস সংযোগ, পেন্ডিং মাইগ্রেশন এবং রেডিস ক্যাশ যাচাই করে।
   - **রেসপন্স (সুস্থ অবস্থায়):**
     ```json
     {
       "status": "ok",
       "database": "connected",
       "migrations": "applied",
       "redis": "connected",
       "uptime": 12450.8,
       "timestamp": "2026-11-22T16:30:00.000Z"
     }
     ```
   - **স্ট্যাটাস কোড:** সুস্থ থাকলে `200 OK`, ডাটাবেস বা মাইগ্রেশনে সমস্যা থাকলে `503 Service Unavailable`।

## ৩. ড্যাশবোর্ড স্বাস্থ্য সতর্কতা ব্যানার (Dashboard Health Alert Banners)

মালিকের ড্যাশবোর্ডে (`/dashboard`) যেকোনো অস্বাভাবিক বা বিপজ্জনক অবস্থা দেখা দিলে স্ক্রিনের শীর্ষে একটি স্পষ্ট লাল ব্যানার প্রদর্শিত হয়:

### ব্যানার ১: ব্যাকআপ পুরোনো হয়ে গেছে (`BACKUP_OVERDUE`)
- **ব্যানার বার্তা:** "সর্বশেষ ব্যাকআপ ২৬ ঘণ্টার বেশি পুরোনো"
- **কারণ:** গত ২৬ ঘণ্টায় কোনো স্বয়ংক্রিয় ডাটাবেস ব্যাকআপ সম্পন্ন হয়নি অথবা ব্যাকআপ ফাইল অনুপস্থিত।
- **করণীয়:**
  1. সার্ভারে লগইন করে ব্যাকআপ স্ক্রিপ্ট রান করুন:
     ```bash
     npm run backup:now
     ```
  2. ক্রোন জব চালু আছে কি না নিশ্চিত করুন:
     ```bash
     crontab -l
     ```
  3. `last-backup.json` ফাইলটির টাইমস্ট্যাম্প ও সাইজ পরীক্ষা করুন।

### ব্যানার ২: শিফট দীর্ঘ সময় ধরে খোলা (`SHIFT_OPEN_EXCEEDED`)
- **ব্যানার বার্তা:** "Xটি শিফট ১৬ ঘণ্টার বেশি সময় ধরে খোলা রয়েছে"
- **কারণ:** কোনো ক্যাশিয়ার দিনের কাজ শেষ করে শিফট ক্লোজ না করেই চলে গেছেন অথবা ক্যাশ কাউন্টার বন্ধ করা হয়নি।
- **করণীয়:**
  1. `/shifts` পেজে যান এবং সংশ্লিষ্ট ব্রাঞ্চের খোলা শিফটটি দেখুন।
  2. ক্যাশিয়ারের সাথে কথা বলে নগদ টাকা গুনে শিফট ক্লোজ করার নির্দেশ দিন।
  3. ম্যানেজার বা মালিকের অ্যাকাউন্টের মাধ্যমে শিফট ক্লোজ করে ভ্যারিয়েন্স রেকর্ড করুন।

### ব্যানার ৩: বিক্রয় পর্যালোচনা ফ্ল্যাগ পেন্ডিং (`REVIEW_FLAGS_PENDING`)
- **ব্যানার বার্তা:** "Xটি বিক্রয়ে পর্যালোচনা ফ্ল্যাগ পর্যালোচনার অপেক্ষায় রয়েছে"
- **কারণ:** অফলাইনে বিক্রির পর মূল্যে পরিবর্তন (`PRICE_CHANGED`), প্রোমোশন অমিল (`PROMOTION_CHANGED`), অথবা ম্যানেজার ওভাররাইড ছাড়া রিটার্ন রিজেক্ট (`RETURN_REJECTED`) হয়েছে।
- **করণীয়:**
  1. `/sales/offline-review` পেজে যান।
  2. ফ্ল্যাগড বিক্রয়গুলোর আইটেম ও মূল্যের ব্যবধান পর্যালোচনা করুন।
  3. "অনুমোদন করুন" (Resolve) বোতামে ক্লিক করে অডিট নোটে কারণ লিখুন।

### ব্যানার ৪: টার্মিনালে অফলাইন বিক্রয় আটকে আছে (`OFFLINE_SYNC_OVERDUE`)
- **ব্যানার বার্তা:** "টার্মিনালে ২৪ ঘণ্টার বেশি পুরোনো সিঙ্ক না হওয়া অফলাইন বিক্রয় রয়েছে"
- **কারণ:** বিক্রয় কাউন্টারের ব্রাউজারে বা ডিভাইসে ইন্টারনেট বিচ্ছিন্ন অবস্থায় বিক্রি হয়েছিল, কিন্তু ২৪ ঘণ্টায়ও তা সার্ভারের সাথে সিঙ্ক হয়নি।
- **করণীয়:**
  1. কাউন্টার কম্পিউটারে ইন্টারনেট ক্যাবল বা ওয়াইফাই চেক করুন।
  2. ব্রাউজারে `/pos` রিফ্রেশ করে হেডার পিলের অবস্থা দেখুন (অফলাইন / সিঙ্ক হচ্ছে)।
  3. ব্রাউজার ক্যাশ বা কুকিজ ডিলিট করবেন না; ইন্টারনেট ফিরে এলে স্বয়ংক্রিয়ভাবে সবগুলো বিক্রয় সার্ভারে আপলোড হয়ে যাবে।

## ৪. প্রতিদিন রাত ১১:৩০ এর স্বয়ংক্রিয় অডিট সামারি (Daily 23:30 Health Audit)

প্রতিদিন রাত ১১:৩০-এ (বাংলাদেশ সময়) ব্যাকএন্ডের একটি শিডিউলড ব্যাকগ্রাউন্ড জব স্বয়ংক্রিয়ভাবে চলে এবং ডাটাবেসের অডিট লগে `DAILY_HEALTH_SUMMARY` শিরোনামে একটি এন্ট্রি সংরক্ষণ করে। 

অডিট লগ দেখতে:
- অ্যাডমিন প্যানেলের `/settings/audit` পেজে যান।
- অ্যাকশন ফিল্টারে `DAILY_HEALTH_SUMMARY` সিলেক্ট করে আগের দিনগুলোর ব্যাকআপ ও শিফট স্ট্যাটাস বিস্তারিত যাচাই করুন।
